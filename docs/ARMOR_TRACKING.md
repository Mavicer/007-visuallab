# 装甲板强化训练与追踪优化报告

日期：2026-10-17。范围为现有“中心加号 + 四角图案”的打印模拟标记，不等同于真实 RM 装甲板或任意新图案检测。

## 1. 原因与处理

原来的定位器寻找中心文字，拖尾又依赖 OCR 恰好输出 `+`。漏读、方向恢复和重复 OCR 都会影响动效的连续性；显示关联本身也不能代替图像追踪。本轮增加可选整板 YOLO 通道，直接检出整个标记，不经过 OCR。通用 ASCII 路线独立保留。

- 新模块 `tracking.py`：每帧一次检测，按位置和尺度关联；仅在短暂漏检时使用 LK 光流。光流需通过前后向一致性、RANSAC 内点比例、特征分布、尺度和旋转检查，最多 3 帧/0.18 秒，不会延长模型确认时间。
- 0.5 秒未得到模型确认后重新获取；多目标歧义暂停输出，远处目标不能直接接管。新 ID 会清除旧拖尾。没有长期重识别、运动预测或云台控制。
- `trajectory.py`：源画面 1080p 时核心线约 11px（原 2px），三倍宽柔光、亮色内芯和最多 96 个短寿命粒子。按时间衰减，只装饰显示副本；真实漏失依然断线。已有追踪结果不再接受第二次更紧的显示距离筛选。
- 界面/终端显示 detector、flow、lost、ambiguous 与短时 ID；flow 不伪造模型置信分数。S 保存无标注原图，T 开关动效、C 清除显示历史。

## 2. 数据与训练

查收 65 张新增 PNG：43 张目标可见，22 张目标已离开画面。人工按整板重新标注并逐一复核，包含模糊、移动和部分出画。历史中心文字框不直接作为整板真值；旧配对纸卡只标记模拟装甲板。

整合 155 张审查记录：训练 55（24 正、31 负），验证 41（13 正、28 负），检查 27（10 正、17 负）；23 张近邻仅回放、8 张间隔保护帧、1 张侧立无法可靠标注的图片排除。新段采用连续区块并留间隔，非相邻帧随机拆分；旧窗帘运动为训练、教室姿态为验证、旧配对标记段为检查。仍共享实体标记和部分房间，并非新场景泛化实验。

仅一次训练：从 text-pilot-v1 初始化，单类 armor，CPU、640、batch/nbs=4、冻结骨干前 10 层、AdamW、最多 20 轮，17 轮早停、最佳第 12 轮，208.3 秒。旋转 ±60°、小幅透视/亮度增强，无镜像和 mosaic；保留真实模糊正样本。请求 torch 4 线程，但框架可能重设线程，未将其宣称为实际线程数。没有 OCR 训练、模型下载或参数搜索。

## 3. 必须保留的失败与阈值取舍

原始 conf=.25 检查为 10 TP、6 FP、0 FN，新增无目标段有 12 帧误检笔记本电脑；初始配置未通过交付门槛。证据保留在 本地实验原始评估/序列文件，不能以最终数字覆盖失败。

验证正样本分数至少约 .647，负误检最高约 .337。因此对装甲板通道采用一次保守的 .5 接受阈值，未做网格搜索或再次训练；该阈值不改通用 OCR 路线。检查帧已在调试中看过，阈值调整后的成绩属于开发检查，不是全新的盲测。

最终固定 conf=.5、整板 IoU>=.5：

| 范围 | 检出 | 假阳性 | 漏检 |
|---|---:|---:|---:|
| 验证 13 张正 + 28 张负 | 13 | 0 | 0 |
| 检查 10 张正 + 17 张负 | 8 | 0 | 2 |
| 全部新增 43 张目标可见（含训练/邻近） | 43 | 0 | 0 |
| 新增 22 张目标离开画面 | 0 | 0 | 0 |

两张检查漏检来自旧“7 + 标记”同框的小标记，不能宣称小目标/多卡问题解决。另有 3 张旧快速模糊图片虽然输出框但 IoU 不达标（其中 1 张训练、2 张近邻）。旧 OCR 通道在新增 43 张中仅 20 张在目标内接受 `+`；这个数字是字符触发成功，不与整板检测 IoU 当作同一种准确率。

## 4. 速度与自查

同机热身后的 65 张源图：旧通道处理耗时中位约 54.7ms、新整板模型约 27.0ms；整板检测加追踪/诊断约 27.6ms，动效绘制中位约 0.84ms、P95约2.20ms。上述不含摄像头取流、GUI 显示和排队延迟，不能倒数称为摄像头 FPS。CLI 冷启动约 0.7～1 秒与热身结果不同。

79 项测试通过：真实图像平移的光流、目标消失、超时、三帧上限、多目标歧义、快速位移、不改源图/回调坐标、实际预览循环和旧路线回归。实际 `run visuallab armor --image ...` 快捷入口已在项目外执行成功。

保存帧约 3 FPS，回放 43 张均保持一个短时 ID，随后 22 张无输出；没有高帧率真实视频证据。光流续接仅有合成图像测试，不能据此宣称真实高速或遮挡追踪已验收。没有实际再次访问摄像头。

## 5. 启动与验收

```bash
run visuallab armor
# 原通用字符识别
run visuallab
```

1. 单块标记静止、横移、旋转：观察 detector 与框是否贴合；确认加粗轨迹和粒子跟随。
2. 快速往返：关注终端实际循环 FPS 和推理耗时；flow 只允许很短时间出现。严重模糊时可失去目标，不应长时间跟着脸、手或电脑。
3. 完全拿走目标至少 3 秒：应 lost、无新框；历史动效约 1.5 秒自然淡出。
4. 重新进入画面：新 ID、新轨迹；同时出现两块近邻标记时应暂停而非任意串目标。
5. 切回普通 run visuallab 检查数字/字符仍走原模型；装甲板模式不会读取板上字符。

值得学习：检测与 OCR 的职责区别；检测确认与光流测量的区别；阈值对误检和小目标召回的取舍。下一步先用户真实摄像头验收；优先补短视频以评估帧间误差和延迟，再决定是否需要运动模糊训练或最新帧取流，不追加盲目训练。
